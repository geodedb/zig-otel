## 5. Per-Gap Acceptance Criteria

### 5.1 PR-1 — MeterProvider.pointFor race (#135)

- [ ] All `inst.points` mutations and `points_index` reads/writes happen under the per-instrument mutex (or are converted to a lock-free structure with arena-of-snapshots semantics — mutex is the simpler win).
- [ ] No `&inst.points.items[idx]` pointer is held across an operation that can grow the underlying ArrayList.
- [ ] Regression test: at minimum a single-threaded "shape-stable" test that exercises grow + concurrent-style index reuse; ideally a 2-thread record-vs-collect stress test (TSan or volatile-counter assertion) that fails on `main` and passes after.
- [ ] `zig build test` green; `make test-all` green.
- [ ] Hot-path perf within ±5% of `bench-hard-criteria` reference; recorded in commit message.

### 5.2 PR-2 — commitSubMessage quadratic copyForwards (#36)

- [ ] Two-pass encode: pass 1 measures child sub-message size, pass 2 writes header + body in place. No `copyForwards` of payload tail per nested commit.
- [ ] No public/generated API change — call sites of `commitSubMessage` unchanged.
- [ ] Wire-format parity test: encode a deeply-nested OTLP payload (≥5 levels) and byte-compare against the previous output (golden bytes captured before the rewrite).
- [ ] All existing tests pass.
- [ ] Nested-encode benchmark from `bench-hard-criteria` shows the ratio shrinks from O(N²) toward O(N) for body bytes; record before/after numbers in the commit message.

### 5.3 PR-3 — Trace encoder items[0]-only scope (#136)

- [ ] Encoder groups the input span batch by `instrumentation_scope` identity (pointer or fingerprint) and emits one `ScopeSpans` per bucket.
- [ ] New test in `test/exporters/` covering a multi-scope batch (≥2 distinct scopes, ≥3 spans across them); test fails on `main` (currently every span beyond items[0] is mislabeled), passes after.
- [ ] No throughput regression on single-scope batches (bench).
- [ ] Public API of the encoder (`encodeTracesProto` etc.) unchanged.

### 5.4 OTEL-Q-001 — otlp_http.zig split (#149)

- [ ] `src/exporters/otlp_http.zig` becomes a thin façade re-exporting symbols from a new `src/exporters/otlp_http/` package: `spans.zig`, `metrics.zig`, `logs.zig` (placeholder OK if logs export still missing per OTEL-Q-003), `encode_proto.zig`, `encode_json.zig`, `transport.zig`, `headers.zig`.
- [ ] Largest single file in the new tree is **<600 LOC**.
- [ ] No caller outside `src/exporters/` changes; the existing public symbols remain importable from `otlp_http.zig`.
- [ ] All existing tests pass with no test-file edits (proves API surface preserved).
- [ ] Triple-encoder family (`encodeMetricsJson`/`encodeMetricsDevnw`/`encodeMetricsStd` and the spans equivalent) collapses to one encoder per signal/wire-format pair, OR is preserved verbatim with a TODO if collapsing exceeds this PR's budget. Document the choice.

### 5.5 OTEL-Q-NEW-A — Tagged-union Transport (#163)

- [ ] Replace the `self.transport == httpTransport` fn-pointer-identity sentinel with `Transport = union(enum) { stdlib_io, custom: *const fn(...) ... }`.
- [ ] All dispatch sites use exhaustive `switch` on the tag; no fn-ptr equality compares remain (`grep -n 'self.transport ==' src/exporters/` returns no hits).
- [ ] All existing tests pass (transport choice verified by behaviour, not identity).
- [ ] Lands inside the OTEL-Q-001 refactor commit (or as a tightly-coupled second commit that imports the new `transport.zig`).

### 5.6 NEW-H-1 — Manifest provenance gate (#134, confidential)

- [ ] `docs/proto-manifest.txt` and `docs/semconv-manifest.txt` include hashes of the actual upstream `.proto` / model-yaml tree under `third_party/opentelemetry-proto-v1.10.0/` and `third_party/semantic-conventions-v1.40.0/` — not just `LICENSE`.
- [ ] If the upstream payloads are not present locally (current state: only `LICENSE` exists), restore them from upstream tarballs and pin by SHA, OR document the deferred path explicitly.
- [ ] `tools/gen_otlp.zig` and `tools/gen_semconv.zig` fail loudly (non-zero exit, clear message) if the `third_party/` dir holds only `LICENSE` and no spec files. No more silent "deterministic provenance" theatre.

## 8. Risk & Blocker Notes

- **PR-1 reproducibility risk**: race conditions are notoriously hard to reproduce deterministically in a Zig 0.16 test harness without TSan. Mitigation: a single-threaded shape-stable test that simulates the grow + dangling-pointer sequence is the floor; the multi-thread stress test is the ceiling. Both should be attempted; the floor is the gate.
- **PR-2 wire-format risk**: byte-compatibility regression is subtle. Mitigation: capture golden bytes from `main` before the rewrite, hard-assert in the new test.
- **PR-3 scope-identity choice**: pointer-equality vs fingerprint-equality on `instrumentation_scope` matters for performance (PR-5 #138 is the follow-up that turns this into a hash-keyed bucket). Use a simple linear scan now per PERF_GAP_ANALYSIS dependency note ("PR-3 introduces groupByScope; PR-5 replaces its linear scan").
- **OTEL-Q-001 budget risk**: 1407 LOC → 7 files is a large diff. If collapsing the triple-encoder family would push the PR over a reasonable review budget, defer collapsing to OTEL-Q-NEW-B (out of scope) and just split the file in this phase. Document the choice in the commit body.
- **NEW-H-1 third-party payload risk**: if the upstream proto/semconv tarballs aren't checked in (currently confirmed: only `LICENSE` is present), restoring them may add MB-scale bytes to the repo. Mitigation: confirm the project policy on vendored spec trees with the user before bulking the repo, or use a SHA-pinned generator script that downloads + verifies on demand.
- **No fuzzing / no Windows tests in CI**: per AUDIT_SUMMARY blockers. Local manual verification only for those surfaces.
- **No SBOM/CVE scanner locally**: not relevant to these 6 items but flagged in the audit; out of scope here.
